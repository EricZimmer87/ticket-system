# Ticket System API

## Overview

Ticket System API is a backend-only help desk and issue tracking application built with ASP.NET Core Web API. The project was created as a learning exercise to gain hands-on experience with modern .NET development, REST APIs, ASP.NET Identity, Entity Framework Core, authentication, authorization, database design, and API architecture.

The application allows authenticated users to create support tickets, track ticket status and priority, and add comments to tickets. The project focuses on backend functionality and does not include a frontend user interface.

## Technologies

- ASP.NET Core Web API
- C#
- Entity Framework Core
- SQL Server
- ASP.NET Identity
- Swagger / OpenAPI

## Authentication

Authentication is implemented using ASP.NET Identity.

The application uses:

- `IdentityDbContext<AppUser>`
- Built-in Identity API endpoints
- Identity user management tables generated by Entity Framework Core migrations

Identity provides the following database tables:

- AspNetUsers
- AspNetRoles
- AspNetUserRoles
- AspNetUserClaims
- AspNetRoleClaims
- AspNetUserLogins
- AspNetUserTokens

Custom application users are represented by the `AppUser` class, which inherits from `IdentityUser`.

## Database Design

The application currently consists of three primary entities:

### AppUser

Represents an authenticated user of the system.

Relationships:

- One user can create many tickets
- One user can update many tickets
- One user can create many comments

### Ticket

Represents a support request or issue.

Properties include:

- TicketId
- CreatedAt
- UpdatedAt
- Title
- Description
- Status
- Priority
- CreatedByUserId
- UpdatedByUserId

Relationships:

- One ticket belongs to one user (creator)
- One ticket may be updated by one user
- One ticket can have many comments

### Comment

Represents a discussion entry attached to a ticket.

Properties include:

- CommentId
- Message
- CreatedAt
- TicketId
- AppUserId

Relationships:

- One comment belongs to one ticket
- One comment belongs to one user

## Enumerations

### TicketStatus

Used to track the current state of a ticket.

Examples:

- Open
- InProgress
- Resolved
- Closed

### Priority

Used to indicate ticket urgency.

Examples:

- Low
- Medium
- High

## Entity Relationships

AppUser (1) ------ (Many) Tickets Created

AppUser (1) ------ (Many) Tickets Updated

AppUser (1) ------ (Many) Comments

Ticket (1) ------ (Many) Comments

## Delete Behavior

User-to-ticket and user-to-comment relationships use `DeleteBehavior.Restrict`.

This prevents users from being deleted when related tickets or comments exist, preserving historical ticket and comment data.

- Implement authentication and authorization
- Design relational database schemas with Entity Framework Core
- Build RESTful API endpoints
